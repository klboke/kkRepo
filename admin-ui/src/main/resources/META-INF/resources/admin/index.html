Proxy settings

Swift proxy follows the Nexus-compatible GitHub source mode. The remote is fixed to https://github.com/; use the username/token fields for private GitHub repositories. Production SwiftPM clients should always connect to kkrepo over HTTPS.

npm proxy only. A version is hidden from package metadata and its tarball is blocked until this many minutes have passed since publication. Use 0 to disable this policy and preserve existing behavior. This is independent of content and metadata cache max age. Versions with a missing or invalid publish time are blocked while enabled.

Outbound network proxy

Route upstream fetches for this proxy repository through an HTTP or SOCKS proxy (e.g. a corporate Clash on the LAN). Useful when the remote registry (hub.docker.com, pypi.org, ...) is unreachable from the server.

Docker connector

Optional compatibility entrypoint for repository-specific Docker traffic. Leave it disabled to use path-based Docker routing on the main service port; enable it only when clients need a dedicated /v2/ port or isolated upload/download traffic.

Cargo settings

Controls the Cargo registry `auth-required` client hint. Repository access is still decided by anonymous settings and security privileges.

Conan 2 status

Conan 2 revisions are committed when conanmanifest.txt arrives. Recipe/package identities, latest pointers, Browse nodes, and the change outbox are published in one database transaction. Enable the Conan bearer token realm for authenticated Conan CLI login.

APT / Debian settings

Hosted repositories always publish atomically signed Release/InRelease metadata. Proxy passthrough preserves upstream bytes; re-signing publishes only packages that have been completely cached and checksum-verified.

Alpine / APK v2 settings

This generation serves APK v2 APKINDEX.tar.gz. Hosted and group repositories publish fenced, atomic signed snapshots. Proxy passthrough preserves upstream bytes; re-signing requires the upstream public key above.
