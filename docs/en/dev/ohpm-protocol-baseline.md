# OHPM protocol compatibility baseline

`protocol-ohpm` contains protocol models and client request tests. There is no creatable OHPM repository yet. The recording HTTP server in the tests is not a kkrepo implementation.

## Sources and verified client

- [Current Huawei protocol](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/ide-interface-protocol), updated 2026-10-10.
- [Huawei V5 protocol](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V5/ide-interface-protocol-V5), updated 2025-01-17 and referenced by the original design.
- OHPM 6.0.1 distributed with DevEco Studio, invoked as a real subprocess against a temporary loopback server.

Important differences from npm and the older design:

- Configure `//host/repository/name/:_auth` or `:_read_auth`; OHPM sends the raw token in `Authorization`.
- Ping requires no authentication according to the official protocol. Package metadata and downloads still follow repository READ permissions.
- Package identifiers are lowercase and at most 128 characters. Parse percent encoding once, including encoded scope separators; preserve scoped download filenames after `/-/`.
- Dist-tag creation and updates send `{"version":"1.2.3"}`. A publish with `--tag beta` need not include `latest`.
- OHPM 6.0.1 unpublishes using a DELETE JSON body containing `version`. An empty version, sent by `--force`, selects the whole package. Support the legacy V5 `@version` URL suffix too, rejecting invalid bodies and conflicting selectors.
- HSP publication can put `hspType` at the metadata root; `resolved_hsp` is generated by the server and need not exist in the publish request.
- Above the default 5 MB threshold, publication uses multipart `metadata` and `pkg_stream`. A stream 404 causes fallback to attachment JSON, verified for both HAR and HSP.
- Although the documentation describes automatic retry on 598, the tested 6.0.1 normal uploader reports failure without retrying. Tests preserve this observation and verify an explicit retry. Do not rely on automatic retry for correctness.

The current documentation also describes compact metadata, `login_pss`, Versions and CheckUpdate. These are not implemented by the protocol foundation and require separate compatibility work if added to the original scope.

## Fixtures and execution

`OhpmFixture` generates small and large HAR/HSP fixtures in the test directory. The HAR includes a manifest and entry point; the HSP is a minimal ZIP with `module.json`, bundled with its interface HAR in a tgz. They are protocol fixtures, not device runtime tests. Large fixtures contain deterministic 6 MiB payloads.

`OhpmClientContractTest` exercises normal and stream publication, HAR/HSP checksums and bytes, 404 fallback, ping, tag mutations, both unpublish scopes, HAR installation, and a reported 598 followed by explicit retry. The legacy URL selector is covered by Java tests, not a claimed execution of a legacy client.

With JDK 25 and Maven 3.9+:

```bash
mvn -pl protocol-ohpm -am test
mvn -pl compat-test -am \
  -Dtest=OhpmClientContractTest \
  -Dsurefire.failIfNoSpecifiedTests=false \
  -Dkkrepo.ohpm.client=true \
  -Dkkrepo.ohpm.expectedVersion=6.0.1 \
  test
```

Install OHPM and its supported Node.js runtime using Huawei's tools. Set `-Dkkrepo.ohpm.command=/absolute/path/to/ohpm` if it is not on PATH. Explicitly enabled client tests fail on a missing executable or a version mismatch. Default CI skips them unless enabled.

Tests use local configuration, a temporary cache and loopback endpoints, without publishing to a public registry. This baseline does not establish kkrepo storage, authorization, concurrency, proxy/group, import or multi-replica correctness; those need server and black-box tests as implementation proceeds.
