# Composer Proxy 元数据性能基线

本文记录 [Issue #425](https://github.com/klboke/kkRepo/issues/425) 的本地排查，以及
[PR #426](https://github.com/klboke/kkRepo/pull/426) 候选修复的实测结果。测量范围是缓存命中时的
元数据获取和依赖解析，不包含制品下载、解压和项目脚本、插件执行，不代表生产容量或完整安装耗时。

[英文版本](../../en/dev/composer-performance-baseline.md) 包含相同数据。

## 原因与优化方式

原先读取已缓存的 p2 元数据时，会为每个历史版本重复保存私有下载路由，最终返回 `304` 的请求也
会经过这条路径。即使路由内容没有变化，仍会重复执行 blob/asset 持久化、组件搜索索引更新和仓库
共享缓存版本号递增。

修复后，每批最多读取 256 个路径对应的路由记录及 blob 大小、SHA-256，仅将缺失或内容变化的路由
交给原来的事务写入流程。判定依据是共享数据库，新副本也能跳过未变化的路由，不依赖单机缓存。
缺失的绑定或中断的填充会在后续元数据请求中补齐；上游 URL、校验和发生变化时仍更新路由，元数据中
已移除版本的路由仍为旧 lock 文件保留。

无需数据库迁移或额外配置。首次填充仍需创建必要的路由记录；本次数据不代表修复构建的冷缓存填充性能。

## 修复前后对照

main 和修复构建依次运行，复用同一个已预热的数据库、blob 存储和客户端缓存。每次调用前删除项目
lock 文件以强制重新解析，同时保留缓存。

| 缓存命中时的操作 | main | 修复构建 |
| --- | ---: | ---: |
| 元数据获取与依赖解析 | 109.126 秒 | 9.101 秒；复测 5.723 秒 |
| `p2/symfony/console.json` GET | 5.731 秒 | 0.070 秒 |
| 同一 p2 的条件 GET（`304`） | 7.692 秒 | 0.063 秒 |
| 每轮解析的路由 asset 更新次数 | 25,276 | 0 |
| 每轮解析的组件搜索索引 upsert 次数 | 25,276 | 0 |
| 每轮解析的仓库缓存版本递增次数 | 25,276 | 0 |

SQL 次数来自 PostgreSQL `pg_stat_statements`。main 与修复构建的 p2 响应体字节一致。
main 每次 GET/304 都写入 685 条路由，修复后这些请求没有路由写入。
表中的 0 指这些路由相关写入，不表示请求完全不访问数据库。

## Nexus 与 Packagist 对照

后续对照使用不含 `vendor` 的独立项目目录、已预热的客户端和服务端元数据缓存，按 Nexus、修复后
kkRepo、直连 Packagist 的顺序依次执行三轮。每轮只删除项目 lock 文件，九次运行的包名、版本和
dist 引用全部一致。

| 缓存命中时的解析 | 第 1 轮 | 第 2 轮 | 第 3 轮 | 中位数 |
| --- | ---: | ---: | ---: | ---: |
| Nexus 3.94.0 | 9.491 秒 | 9.083 秒 | 9.176 秒 | **9.176 秒** |
| 修复后 kkRepo | 4.207 秒 | 4.471 秒 | 4.081 秒 | **4.207 秒** |
| 直连 Packagist | 7.569 秒 | 9.081 秒 | 9.191 秒 | **9.081 秒** |

Nexus 在仓库与客户端缓存均为空时的首次运行耗时为 15.250 秒。热缓存数据仅代表这组本地部署，
不能据此推断不同存储后端、远程数据库、S3、网络条件和并发负载下的通用性能排序。
实时 Packagist 内容也可能在后续发生变化。

## 复测方法

1. 采用 Issue #425 中的 `composer.json`，各目标保持相同的 27 项依赖，统一设置
   `symfony/twig-bundle:^7.4` 与 `config.platform.php=8.3.0`。
2. 创建独立的临时项目目录和 Composer 缓存目录。测试 proxy 时配置其仓库根 URL，并关闭默认
   Packagist；直连 Packagist 时不添加该覆盖配置。
3. 先运行一次填充缓存。测量缓存命中时保留仓库与客户端缓存，删除临时项目生成的 `composer.lock`，
   使用相同命令执行：

```bash
composer update --no-install --no-scripts --no-plugins \
  '--ignore-platform-req=ext-*' --no-interaction --no-audit -vvv --profile
```

4. 测量进程实际耗时，保留各轮生成的 lock 文件，核对包名、版本和 dist 引用；dist URL 的主机随目标
   不同。依次运行各目标以避免测试之间争抢资源，重复三轮，记录全部样本及中位数。保持客户端版本和
   platform 配置不变，不把依赖下载或项目脚本执行混入该计时范围。

## 正确性验证

- MySQL 8.0 和 PostgreSQL 12 的双副本测试覆盖 proxy/group 的缓存 GET、HEAD、条件 GET，确认路由
  绑定、时间戳和缓存版本号不变，并验证上游路由更新后另一副本能下载到新内容。
- Nexus 3.94.0 实例兼容测试覆盖重复读取的元数据字节与 HTTP validator、条件 `304`、公开下载路径
  和制品下载。
- 独立的真实 Composer 安装验证成功下载并解压全部 99 个包；关闭了项目脚本和插件，忽略了扩展平台
  要求。该安装耗时未计入上述解析表格。

客户端配置见 [Composer 仓库使用指南](../repository-guides/composer-php.md)。
