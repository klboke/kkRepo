# 最小发布时长（隔离期）

**代理仓库**可以拒绝提供发布时间不足指定分钟数的版本。被劫持的维护者账号或恶意发布的包通常会在数小时内被发现并从上游撤下，因此把隔离期设为 48 小时（`2880` 分钟），被投毒的版本通常在任何构建通过 kkrepo 拉取之前就已被撤回。Hosted 仓库不受影响；默认值 `0` 表示关闭。对 Go 而言，时间按提交时间而非发布时间计算，防护较弱（见[上游要求](#上游要求)）。

在 npm、Go、Maven 或 PyPI 代理仓库的 **Proxy settings → Minimum release age (min)** 中设置，或在 `/internal/repositories` 中设置 `proxy.minimumReleaseAgeMinutes`。仓库组没有独立配置：它沿用代理成员的策略，不会过滤 hosted 成员。

## 行为

| 格式 | 发布时间来源（Go：提交时间） | 索引 / 元数据 | 直接下载过新版本 |
| --- | --- | --- | --- |
| npm | packument 中的 `time` | 隐藏版本并修正 dist-tags | 404 |
| Go | `<version>.info` 中的 `Time`（**提交**时间，见下文） | 从 `@v/list` 隐藏；`@latest` 回退到最新的已过隔离期版本（没有则 404） | `.info`、`.mod`、`.zip` 返回 403 |
| Maven | 版本 `.pom` 的上游 `Last-Modified` | 从 artifact 级 `maven-metadata.xml` 隐藏，重算 `latest`/`release`，元数据校验和由改写后的文档生成 | 该版本的所有文件、校验和与签名返回 403 |
| PyPI | PEP 700 `upload-time` | 从项目页隐藏文件（全部被隐藏时 404） | 403 |

403 响应会说明制品名称以及还需多久可用，并带有 `Cache-Control: no-store`。拒绝结果不会被当作“不存在”缓存，版本一旦过了隔离期就会立即出现。npm 保持原有 404，以便 npm 客户端回退到更旧的版本。

**无法确定发布时间的版本按隔离处理**（失败即关闭）。Maven SNAPSHOT 版本及其元数据不受限制，因为它们可变且没有有意义的发布时间。

## 对客户端的影响

- **Go**：`go` 把 403 视为硬错误，不会尝试 `GOPROXY` 中的下一项（除非用 `|` 分隔）。这是有意为之，避免误从源站拉取过新版本。
- **Maven**：403 会使构建以传输错误失败，而不是被记为缺失。仍在隔离期的固定版本会明确报错。
- **PyPI**：`pip` 基于过滤后的项目页解析，会选择更旧的版本；固定到隔离期内的文件会得到 HTTP 403。

## 上游要求

- **PyPI** 需要上游提供带 PEP 700 `upload-time` 的 PEP 691 JSON simple 索引（例如 pypi.org）。只提供 HTML 的上游（Nexus、Artifactory）会返回 502 并给出说明，而不是静默返回未过滤的内容。
- **Maven** 依赖上游保留文件原始的 `Last-Modified`。如果镜像站把自己的同步时间写入该头，所有版本都会显得很新。
- **Go** 衡量的是**提交时间**，而不是发布时间。在 GOPROXY 协议中，不仅伪版本，普通打标签版本的 `Time` 也是提交时间（Go 工具链读取 `git log %ct`）。因此隔离期只能防护“刚提交的代码”：今天在早于隔离期的旧提交上新打的标签会被立即放行，提交日期也可以被作者回填伪造。Go 的隔离是比 npm、Maven、PyPI（时间戳来自仓库本身）更弱的防护。对绝不应来自公共上游的内部命名空间，请同时使用[路由规则](routing-rules.md)。

## 多副本语义

所有判定都来自共享状态（数据库和 blob 存储中缓存的上游响应）。每个节点只保留有界、可重建的版本发布时间缓存（不可变值，按仓库**和上游 URL**作为键，因此修改代理的远端 URL 不会沿用旧上游的时间；写入后保留 6 小时），丢失只会多一次查询。过滤后的 Go 列表、Maven 元数据和 PyPI 页面在每次请求时重新计算，因此版本一过隔离期就会出现，即使原始上游文档仍按正常的最大缓存时间缓存。包含受限代理的 Maven 组合并元数据和 PyPI 组索引至少每 10 分钟重新合并一次，原因相同。

## 限制

- Go 模块的首次 `@v/list`，以及 Maven artifact 的首次元数据请求，会对每个版本做一次上游查询（有界并发）；之后使用缓存。
- 调高最小发布时长不会清除 Maven 组已从成员缓存的内容，它会随组的内容最大缓存时间过期。
- 已缓存的内容同样受限：年龄检查在访问缓存之前执行。
